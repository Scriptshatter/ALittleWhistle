Some some docs on A Little Whistle!
A Little Whistle is pretty powerful for what it is, so this is here to help you with any questions you may have.

FEATURES:
    ADDITIOAL DIALOUGE FUNCTIONS
    These can be accessed by doing ["_func", [["removeObject", ["(Function name)", (Arguments)]]]]
    This is because removeObject act as a proxy by which to run these custom functions.
    That aside, what are they? And what can you do with them?
    Well:
        font (["font", starting character index, ending character index, "(Font Name)"]) This changes the font, pretty self explanitory (NOTE: Remember to use » since line breaks dont always properly calculate with this)
        font_reset (["font_reset"]) This isn't needed, but sometimes after using font the next dialogues line breaks can go all funky. This lets you manually set your own line breaks with ».
        init (["init"]) Generally not needed, but there just in case. This re-indexes all custom assets (which we'll cover in a moment)
        fadeMusic (["fadeMusic", volume, time]) Sometimes fading doesn't work properly for custom music. This targets the first song played, and manually tells the music player to fade it properly!
        replace_asset (["replace_asset", "(Asset name)", "(New asset name)"]) This one's nifty! It lets you replace your characters custom assets in a cutscene, so you can do things like change your camera reflection mid run!
        set_global (["set_global", "(global name)", (new value)]) Exactly what it says on the tin, lets you change a global variable to whatever you want.
        set_quota (["set_quota", new_quota]) Overrides the current quota. Not quite finished yet, as it'll make the quota set here persist to future runs. Is disabled when "mechanics_off.alw" is in the root save folder.
        alw_func (["alw_func", {(Function)}]) We'll go over this later. This one is EXTREMELY powerful, and what I was working on what you messaged me.

    CUSTOM ANIMATRONIC DIALOGUE
    You can replace an animatronics dialouge by putting a json file named after them in the dialogue folder. (Since you've made a data.win mod, it's based off the name of the argument that's put into game_text)
    These have a few special things associated with them that make them different from normal cutscenes. I'll list those out now:
        animatronic_id: This is a special argument you put ALONG SIDE DIALOGUE, not inside the array, beside it. I've left an example for you.
        NOTE: All future custom lines here CANNOT run inside of _split statements yet, unfortunately. Treat these like you would _skip or _delay, so don't put them in a _func. These do not work during normal cutscenes.
        ["_turn_camera"]: Turns your camera to psychic friend fredbear. Used during the salvage intro segments.
        ["_replace_text", "(new text)"]: Replaces the current dialouge with a new dialouge. Used for things like BB's quiz and psychic friend fredbear no long greating after you've entered.
        ["_replace_text_ext", "(old text)", "(new text)"]: Same as the last one, but this one can target anything, not just the text you're currently in.
        ["_scan_array", "(global arrays name)", (index)]: Depricated, but I'll put it here for full coverage. Grabs the requested index of an array and saves it to a global variable called "array_result".
        ["_bb_ask", index]: This is used for when balloon boy asks you questions. I'll cover how this specifically works in a bit.

    ALW CHARACTER DATA
    Stored in the file "alw_character_data.json" in the root directory of your character, this stores all ALW specific data. This includes 3 main feilds:
    "bb_questions": [] Remember this from before? Yup, this is where _bb_ask comes into play. This an an array of arrays of questions. depending on the index, a specific list of quesions will be chosen. I've left a small example in this folder.
    "backgrounds": {"(Cutscene name)": "(Name of new bacground asset)"} For custom cutscene backgrounds! Just put the name of the cutscene on the left side, and the name of the new asset on the right
    "replacement_themes": {"(old theme)": "(new theme)"} Same pattern here. Put the name of the audio file you wanna replace on the left, and the name of the audio file you wanna replace it WITH on the right.

    FILE HANDLING
    There are two additional folders you can include in your character with ALW, that being custom_assets, and talkSounds.
    talkSounds: Simply place the talksound as an ogg, name it after the character, and there you go! If you put the name of the file as a speaker in a cutscene (Minus the .ogg, of course), it'll play that talksound for them.
    custom_assets: Same as talkSounds, but with assets! You can put folders in here filled with images of sprites to make sprites with more than one image. When doing this, you may number the sprites using their names to determine the order they will be added. You may also include a JSON file as the FIRST. FILE. do determine if it's a font, it's font key if it is one, and it's X and Y offsets (Those last two are useful for talksprites!) I'll supply a talksprite of The Boss made by Epic on discord as an example. (This is also how you add custom fonts and sounds. Just plug their file names minus the extension into anywhere you'd normally grab an asset by name in dialouge and it'll grab your custom asset.)

    ALW FUNCTIONS:
    A little of a last minute addition. Here's how they work: Not only are they a function, they can also be used in _split in place of a global variable name.
        {
            "alw_type": (Either a number or string),
            "args": [Arguments]
        } OR
        {
            "alw_type": "(Symbol (Symbols being +, -, /, *, %, >, <, <=, >=, ==, &&, and ||))",
            "left": (Left argument),
            "right": (Right argument)
        }
    Ok, so, 1. You can nest arguments. An ALW function CAN be an argument here, which is nice.
    2. When it comes to the top, you can either put the ID of the function, or the name of a function. Putting the name of a function, do note, only works with functions defined in the data.win.
    3. I've provided a list of all built in function IDs for you to use.

... I think that's everything? Keep in mind this thing may be a liiiitle unstable as it's directly interfacing with memory.
